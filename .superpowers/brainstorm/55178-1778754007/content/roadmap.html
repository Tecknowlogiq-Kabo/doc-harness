DocHarness Enhancement Roadmap

18 enhancements across 4 tracks — what order should we build?

Current State: AI Doc Gen Platform

  • 6-phase pipeline with 25 AI agents + adversarial debate
  • 18 document types (PRDs, ADRs, SRS, etc.)
  • Next.js web UI with real-time SSE streaming
  • Zero persistent storage. Zero tests beyond 3 utility modules. No file output.

Proposed: 4-Track Enhancement Plan

1

Output & Downloads

ZIP download, clipboard copy, file output to disk, export to Notion/Google Docs

2

Persistent Storage

SQLite/D1 session storage, document versioning, history browser, session sharing

3

Web UI Polish

Tailwind CSS, error recovery, retry, loading states, diff view, graph viz

4

Production Hardening

Tests, pipeline cancellation, env validation, config system, CLI tool, README

Recommended: Build in this order

Tracks build on each other. Output → Storage → UI → Hardening.
